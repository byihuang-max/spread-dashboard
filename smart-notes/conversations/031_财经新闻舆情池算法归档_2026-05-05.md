## 数据源

**100% Tushare Pro**，不调外部 LLM 做抓取。

- 接口：`pro.news(src=..., start_date=..., end_date=...)`
- 三个源：`wallstreetcn`（华尔街见闻）、`cls`（财联社）、`sina`（新浪财经）
- 时间窗：最近 **12 小时**
- LLM（`gpt-5.4` via aicanapi 中转）**只用于动态主题发现**，不参与抓取

## 算法五步

### 1. 抓取 + 合并去重

```text
for src in [wallstreetcn, cls, sina]:
    pro.news(src, start=now-12h, end=now)
→ 合并
→ 按「标题字符串完全匹配」去重（seen_titles set）
→ 按时间倒序排序
```

去重规则就一句：`if title not in seen_titles: keep`。简单字符串完全匹配，对"同一条新闻被三家转发"够用。

### 2. 四个固定叙事匹配

硬编码关键词库（NARRATIVES dict）：

| 叙事 | 代表关键词 |
|---|---|
| 地缘风险 | 以色列、伊朗、哈马斯、俄乌、台海、霍尔木兹、制裁 |
| AI_CapEx | 英伟达、H100/H200/B200、Blackwell、HBM、CoWoS、OpenAI 融资、Anthropic |
| 中国政策 | 政治局会议、降准降息、LPR/MLF、特别国债、房地产新政、以旧换新 |
| 全球央行 | 美联储、鲍威尔、FOMC、ECB、拉加德、BOJ、植田和男、YCC |

**匹配规则（权重制）：**

```text
标题命中 ≥ 1 个关键词 → 权重 = 命中数 + 10   （强匹配）
正文命中 ≥ 2 个关键词 → 权重 = 命中数         （弱匹配）
（标题命中后直接 continue，不再检查正文）
```

### 3. 热度打分（0–10）

```text
matched_count = 该叙事命中的新闻条数
total_news    = 本次抓取的总新闻数
match_ratio   = matched_count / total_news × 100

score = min(10, int(match_ratio × 2))
```

输出字段：`score / matched_count / total_news / key_news(前3条标题)`。

### 4. LLM 动态主题发现

针对**没被 4 个固定叙事命中**的剩余新闻：

- 取前 **200** 条标题
- 交给 `gpt-5.4`，提示词要求返回 Top **5** 热门主题 JSON：
  ```json
  [{"theme": "...", "count": N, "keywords": [...], "examples": [...]}]
  ```
- 要求：主题名 5–10 字、至少 5 条相关新闻、主题不重叠
- 解析后调 `enrich_dynamic_themes()` 用 keywords 回灌未匹配池，给每条主题挂最多 **8 条**代表新闻（标题/时间/来源）

### 5. 历史对比 + 推送

- 读 `cache/narrative_history.json`，对比上次运行结果
- 计算主题环比：热度上升 / 下降 / 新主题 / 消失
- 组装飞书卡片，推送到 Roni（open_id：`ou_4f9c4d14f2e27f4863a5e2743dba3482`，旧账号）

## 关键参数速查

| 参数 | 值 | 位置 |
|---|---|---|
| 抓取时间窗 | 12h | `fetch_news(hours=12)` |
| 数据源 | wallstreetcn / cls / sina | `fetch_news` |
| 标题命中权重 | +10 | `analyze_fixed_narratives` |
| 正文命中阈值 | ≥ 2 个关键词 | 同上 |
| 打分上限 | 10 | `score = min(10, ...)` |
| LLM 输入标题数 | 前 200 | `discover_dynamic_themes` |
| LLM 返回主题数 | Top 5 | 同上 |
| 动态主题挂载新闻数 | 8 | `enrich_dynamic_themes(max_news=8)` |
| 固定叙事前 3 条新闻展示 | 3 | `key_news[:3]` |

## 前端复用
