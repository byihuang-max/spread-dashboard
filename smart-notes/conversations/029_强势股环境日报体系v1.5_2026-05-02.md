## 日报结构（六节）

### 一、核心指标
- 小字："整体市场强势方向与温度"
- **涨停**（一级粗体）
  - 方向 / 强度 / 额度（灰色缩进）
  - >> 首板 N家（集中/偏集中/分散）
    - 首板方向（深缩进灰色）
  - >> 晋级率 N% | 断板 M/K
    - 晋级方向
  - >> 1进2 N%
    - 1进2方向
  - >> 炸板率 N%
    - 炸板方向
- **跌停**（一级粗体）
  - 方向 / 强度 / 额度
- **封单轧差**（一级粗体，独立指标）

### 二、百亿涨停
- 小字："市场核心聚焦方向"
- 行业标注：申万二级（v1.5 起）

### 三、产业链共振
- 小字："成交额加权强度 + 上下游传导验证"
- 最强链切换/连续提示
- Top 3 链：强度 + 状态 + 排名变化（▲N）
- 其余链一行摘要

### 四、龙头观察池
- 小字："高度 + 成交聚焦的核心票筛选"
- 辨识度龙头（板数标红）+ 换人提示
- 成交额龙头（成交额+板数）+ 换人提示
- 池内变动（新进/退出）
- 池内列表

### 五、ETF 关注
- 小字："综合产业链强度、百亿涨停与龙头方向"
- 逻辑：主攻链 → 链内最强二级行业 → 全市场 ETF 动态匹配（按当天涨幅排序）
- 过滤当天亏钱的 ETF
- 层级：行业方向（主行）→ ETF（灰色缩进）

### 六、结论
- 状态变化 + 灰色小字解释
- 主攻方向（整行标红）+ 灰色小字解释
- 注意事项（整行标红）

## 算法要点

### 产业链强度
```
strength = Σ(行业涨跌幅 × 行业成交额) / Σ(行业成交额)
```
10条链，底层申万二级行业，成交额加权。

### 链状态判断
每层（上/中/下游）等权平均，±0.3% 阈值：
- 全正 → 全链共振
- 全负 → 全链下跌
- 有正有负 → 链内分化
- 单向 → 偏强/偏弱
- 都在阈值内 → 震荡

### ETF 动态匹配
1. 确定方向（产业链+龙头+百亿涨停）
2. 提取方向内最强二级行业
3. 用行业关键词从全市场 ETF 搜索
4. 按当天涨幅排序，取 Top 2
5. 过滤：涨幅 < 0 或成交额 < 1亿 的不推

### 首板集中度
Top3 行业占比：≥40% 集中，25-40% 偏集中，<25% 分散

## 订阅者管理与防丢机制

`email_subscribers.json` 是各环境独立维护的配置文件，**不通过 git 同步**（已加入 `.gitignore`）。

### 历史教训
2026-05-02 发现订阅者从 9 人掉到 4 人。根因：该文件此前被 git track，腾讯云 `deploy_sync.sh`（`git reset --hard`）每次同步都会把它还原成仓库里的旧版本，覆盖掉后续手动添加的订阅者。

### 当前防护
1. **git 隔离：** 文件已从 git 移除 + `.gitignore`，`deploy_sync` 不再触碰
2. **每日备份：** 腾讯云 cron 08:00 自动备份到 `subscriber_backups/`（保留 30 天）
3. **人数校验：** 同一 cron 检查订阅者人数是否 ≥ 预期值（当前 9），异常写入 `/tmp/subscriber_check.log`
4. **校验脚本：** `/home/ubuntu/gamt-dashboard/scripts/check_subscribers.sh`

### 操作规范
- **新增订阅者：** 直接编辑腾讯云上的 `email_subscribers.json`，同时更新 `check_subscribers.sh` 中的 `EXPECTED_MIN`
- **恢复订阅者：** 从 `subscriber_backups/email_subscribers_YYYYMMDD.json` 复制回来
- **本地不维护此文件**，腾讯云为唯一权威源

## 维护

- **日频自动：** 腾讯云 cron 18:05 跑 send_daily_email.py
- **月频手动：** `python3 update_etf_map.py` 检查 ETF 增减
- **迭代记录：** 本文件 + memory/2026-05-02.md
