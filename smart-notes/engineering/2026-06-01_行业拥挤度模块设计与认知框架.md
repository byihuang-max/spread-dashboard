## 一、核心认知框架

### 拥挤度的两个维度

```
┌─────────────────────────────────────────────────────────┐
│                  行业拥挤度 = 两个独立视角               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ① 横截面（自己 vs 全市场）                             │
│     定义：行业成交额 / 全市场成交额                     │
│     含义：这个行业在全市场里"占了多少蛋糕"              │
│     31个申万一级行业合计 = 100%                         │
│                                                         │
│  ② 纵向（自己 vs 自己历史）                             │
│     定义：行业当日成交额 / 自身过去N天均值              │
│     含义：这个行业相对自己历史是在放量还是缩量          │
│     量比 > 1.5 = 显著放量 / < 0.7 = 显著缩量           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 四象限判断矩阵

```
                    纵向量比高（自己在放量）
                         │
         ┌───────────────┼───────────────┐
         │               │               │
         │  占比低+量比高 │  占比高+量比高 │
         │  = 边际升温    │  = 真拥挤      │
         │  (小板块突然   │  (大板块还在   │
         │   有资金涌入)  │   加速吸金)    │
         │               │               │
横截面 ──┼───────────────┼───────────────┼── 横截面
占比低   │               │               │   占比高
         │  占比低+量比低 │  占比高+量比低 │
         │  = 冷门        │  = 假拥挤      │
         │  (没人关注)    │  (占比高只因   │
         │               │   别人缩更多)  │
         │               │               │
         └───────────────┼───────────────┘
                         │
                    纵向量比低（自己在缩量）
```

**核心判断逻辑：**
- 真拥挤 = 占比高 + 自己也在放量 → 资金在加速涌入，警惕见顶
- 假拥挤 = 占比高 + 自己在缩量 → 占比高只是因为别人缩得更多，不是真热
- 边际升温 = 占比低 + 量比高 → 小板块突然活跃，可能有事件驱动
- 冷门 = 占比低 + 量比低 → 无人问津

## 二、页面模块设计（6大模块）

### ① 行业拥挤度占比变化（折线图）
- **含义：** 自身成交额 vs 全市场成交额（横截面视角）
- **展示：** Chart.js 折线图，X轴=日期，Y轴=占比%
- **交互：** 底部进度条双手柄拖拽时间窗口；行业chip切换显示/隐藏
- **默认：** 显示占比TOP5行业，全量5年历史
- **数据源：** share_series.json（1308天 × 31行业）

### ② 行业活跃度（条形图）
- **含义：** 自身成交额 vs 自身历史均值（纵向视角）
- **展示：** 横向条形图，长度=量比，颜色=红(>1.5放量)/绿(<0.7缩量)/橘(正常)
- **交互：** 均值窗口按钮（近3月/6月/1年/2年/3年/全量5年）
- **右侧标注：** 量比倍数 + 占比% + 均值(亿)
- **排序：** 按量比降序
- **数据源：** share_series.json 的 amount 字段

### ③ 拥挤度边际加速 TOP5
- **含义：** 占比的变化量排名（谁在加速流入/撤离）
- **展示：** 4宫格卡片（周度流入/流出 + 月度流入/流出）
- **数据源：** crowding.json → accel_rank

### ④ 量价状态矩阵
- **含义：** 占比边际(量) × 赚钱效应(价) 交叉分类
- **四态：** 量价齐升 / 量升价不跟(见顶预警) / 缩量上涨(持续性存疑) / 量价齐跌
- **叠加：** 占比分位>90% 标拥挤顶风险
- **数据源：** crowding.json → vp_matrix

### ⑤ 行业涨跌家数（breadth）
- **含义：** 每个行业当天上涨/下跌成份股数量
- **展示：** 红绿双色条 + 涨家占比 + 涨停/跌停数
- **交互：** 点击一级行业展开二级明细；可按涨家占比排序
- **数据源：** crowding.json → breadth_l1 / breadth_l2

### ⑥ 时序量比热力图（原有模块保留）
- **含义：** 每个行业成交额/MA20 的量比 + ETF份额变化
- **展示：** 网格卡片，颜色=涨跌幅度，标签=量比/ETF流向
- **数据源：** crowding.json → industry_heatmap

## 三、数据管道架构

```
数据层（每日增量拉取）:
  breadth_data.py
    ├── fetch_share_hist()  → cache/sw_share_hist.csv（31行业日成交额+占比）
    ├── fetch_breadth()     → cache/breadth_l1.csv + breadth_l2.csv（涨跌家数）
    └── 数据源: tushare sw_daily / daily / limit_list_d / index_member

计算层（每日重算）:
  crowding_calc.py → crowding.json（量比热力图 + 信号）
  breadth_calc.py  → crowding.json（横截面 + 加速 + VP矩阵 + breadth + 情绪）
                   → share_series.json（占比+成交额时间序列，前端折线图用）

前端:
  industry_heatmap.html（纯静态，fetch JSON 渲染）
  chart.min.js（本地 Chart.js 4.4.1，不依赖 CDN）

Cron 执行顺序:
  crowding_data.py → breadth_data.py → crowding_calc.py → breadth_calc.py
  时间: 工作日 08:20 (am phase)
```

## 四、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 行业分类 | 申万一级(31个) | tushare 数据完整，与看板其他模块一致 |
| 历史深度 | 5年(2021-01起) | 覆盖完整牛熊周期，分位才有意义 |
| 分位窗口 | 用户可选(3月~5年) | 不同窗口含义不同，让用户自己判断 |
| 第二张图含义 | 量比(自己vs自己) | 与第一张(自己vs全市场)形成互补，不重复 |
| 条形颜色 | 统一橘色+透明度 | Bloomberg风，不花哨 |
| Chart.js | 本地文件 | jsdelivr 国内不稳定(梯子关时不通) |
| share_series.json | 独立文件(684KB) | 避免 crowding.json 膨胀影响其他模块加载 |
| 折线图交互 | 进度条双手柄 | 比 zoom/pan 插件更直观，用户一看就懂 |

## 五、与其他模块的关系

- **④ 量价状态矩阵** 是 ①②③ 的综合判断层：把占比边际(③的数据) × 赚钱效应(⑤的数据) 交叉分类
- **⑤ breadth** 提供"赚钱效应"的底层数据(涨家占比)
- **⑥ 时序量比热力图** 是更早期的实现(MA20量比)，与②有重叠但保留作为快速一览
