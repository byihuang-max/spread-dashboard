## 正文

# research-capture skill 设计与上线（2026-05-07）

## 需求缘起

Roni 希望"发研报进来就存笔记"——不只是研报，还包括文章、心得、长文、链接。目标：看到好东西只做一个动作就入库。

## 关键设计决策

### 决策 1：定位为"投研材料捕获器"，不是"可视化链接收藏夹"

研究过两条路径：
- **路径 A**：拉专用 bot 群，群内默认自动入库
- **路径 B**：主聊天分享链接 + 补一句"存笔记"

Roni 觉得飞书群麻烦。最终选 **第三条路**：**主聊天 + 短触发词**（`收` / `归档` / `存研报`）。

**选择理由：**
- 群入口虽然语义最清晰，但对单人投喂场景是过度设计
- 主聊天全自动会污染知识库（有时分享只是让我看，不一定要存）
- 短触发词成本最低——只多打一个字
- 未来扩容路径留好了：投喂频率上来再加"投研收件箱"群

### 决策 2：不重造轮子，接 Smart Notes 管线

分类、迭代、落盘、BUILTIN_NOTES 更新全部走现成的 `save_note.py`。新 skill 只做两件事：
1. 抓正文（URL / HTML / 长文）
2. 投研式拆解（调 Claude，统一 schema：一句话结论 / 核心观点 / 关键证据 / 影响资产 / 风险）

### 决策 3：三层触发等级

| 触发 | 行为 |
|------|------|
| 显式词（收/归档/存研报） | 抓取 + 拆解 + 入库 |
| `看一下` / `只摘要` | 只分析，不入库 |
| `暂存` | 存 archive，不升到精选笔记 |
| 默认（无触发词） | 不自动调，避免污染 |

## 技术架构

```
输入（URL/文本/PDF）
    ↓
extract_content.py    抓正文（readability 优先，bs4 兜底）
    ↓
distill.py            调 Claude 做投研拆解（JSON 结构化）
    ↓
render_markdown       生成符合 Smart Notes 格式的 Markdown
    ↓
save_note.py          Smart Notes 管线（embedding 分类 + 迭代检测 + 落盘）
    ↓
飞书回执
```

## 端到端验证

用中信证券 AI CapEx 研报文本测试：
- distill 正确输出结构化 JSON（标题/主题/观点/证据/影响资产/FOF 策略含义/风险）
- Smart Notes 管线分类到 conversations 类（embedding 0.71）
- 迭代检测发现相似笔记（2026-04-26 美股科技周报），但 Claude 判定为独立新笔记
- `--dry` 预览模式正常，不误写

## 已知限制

国内投研网站大多 JS 渲染 + 反爬（华尔街见闻、财联社等），URL 抓取会失败，需要用户贴正文。这是**预期行为**，脚本正确返回 `extract_error`，不伪造内容。

## 长期规则（本次确立）

**新 `.py` 脚本不许写进 workspace。** 统一放 `~/Desktop/gamt-dashboard/` 下面：
- 工程代码：各自模块目录
- Skill 类代码：`skills/<skill-name>/`，必须带 `README.md`（给人看）+ `SKILL.md`（给 AI 触发）
- workspace 只放 MEMORY / USER / SOUL / HEARTBEAT 这类工作台文件

## 方法论沉淀

1. **低摩擦体验 > 强制自动化**。短触发词比拉群/全自动更顺
2. **不重造轮子**。已有管线（Smart Notes）就接，不自己写分类
3. **写完就验**。工具报"成功" ≠ 真落盘，要 `ls -la` + `git status` 双核验
4. **承认边界**。抓不到就说抓不到，不伪造内容
