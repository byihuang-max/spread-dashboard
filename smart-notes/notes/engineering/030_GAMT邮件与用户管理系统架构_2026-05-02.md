## 一、邮件推送系统

### 1.1 架构总览

```
腾讯云 cron (18:00 --late-only 产数据)
        ↓
腾讯云 cron (18:05 send_daily_email.py)
        ↓
momentum_daily_report.py → 生成纯文本日报
        ↓
send_daily_email.py → report_to_html() 渲染 HTML
        ↓
SMTP SSL → smtp.qq.com:465 → 逐个发送给订阅者
```

### 1.2 核心文件

| 文件 | 职责 |
|------|------|
| `env_fit/momentum_stock/send_daily_email.py` | 邮件发送主脚本（HTML渲染 + SMTP发送） |
| `env_fit/momentum_stock/momentum_daily_report.py` | 日报内容生成（纯文本） |
| `env_fit/momentum_stock/email_subscribers.json` | 订阅者配置（腾讯云为准） |
| `env_fit/momentum_stock/email_manage.html` | 前端订阅者管理页面（admin only） |
| `server/refresh_server.py` | 后端 API（GET/POST /api/email-subscribers） |

### 1.3 订阅者配置结构

```json
{
  "subscribers": [
    {"email": "xxx@qq.com", "name": "姓名", "enabled": true}
  ],
  "sender": {
    "email": "854523290@qq.com",
    "smtp_host": "smtp.qq.com",
    "smtp_port": 465,
    "auth_code": "***"
  },
  "settings": {
    "subject_prefix": "强势股环境日报",
    "footer": "GAMT 投研看板 · 自动推送",
    "max_retry": 2
  }
}
```

### 1.4 发送逻辑

1. `send_daily_email.py main()` → 调用 `generate_report()` 生成纯文本
2. `report_to_html(text, footer)` → 渲染为 HTML 邮件（白底黑字，红绿仅涨跌幅）
3. `send_to_all(report_text)` → 遍历 enabled 订阅者，SMTP SSL 逐个发送
4. 每个订阅者最多重试 `max_retry` 次（默认2次），失败间隔2秒

### 1.5 邮件 HTML 排版规则（v4 定稿）

- 白底 `#ffffff`，黑字 `#1a1a1a`，灰色次要信息 `#6b7280`
- 红 `#cc2929`（涨）/ 绿 `#1a8a4a`（跌）仅用在涨跌幅数字
- 字体：系统默认 sans-serif
- 最大宽度 600px，居中

### 1.6 前端管理页（email_manage.html）

- 仅 admin 可访问
- 登录态读取：优先 `gamt_token`，兼容 `auth_token` / `token`
- 功能：查看订阅者列表、添加/删除订阅者、启用/禁用
- 添加时有二次确认弹窗
- 后端保存后自动 git commit + push（异步线程）

### 1.7 关键设计决策

- `email_subscribers.json` 不在 git 同步范围，腾讯云为唯一权威源
- 本地 Mac 不再发邮件，全部由腾讯云 cron 负责
- SMTP 直发，发件箱里看不到副本
- 非交易日暂不发送（待定：Roni 计划加一句话）

## 二、用户管理系统

### 2.1 架构总览

```
前端 index.html (登录/注册)
        ↓
后端 refresh_server.py → auth.py
        ↓
SQLite users.db (server/users.db)
```

### 2.2 核心文件

| 文件 | 职责 |
|------|------|
| `server/auth.py` | 认证核心模块（注册/登录/权限/邀请码） |
| `server/users.db` | SQLite 用户数据库 |
| `admin.html` | 管理后台（用户管理/等级/权限/邀请码/团队） |
| `team.html` | 团队工作台（tier>=2 可访问） |
| `server/refresh_server.py` | 后端 API 路由 |

### 2.3 数据库表结构

| 表 | 用途 |
|----|------|
| `users` | 用户主表（id, username, display_name, password_hash, salt, is_admin, tier, status, login_count...） |
| `sessions` | 登录会话（token, user_id, expires_at） |
| `login_log` | 登录日志（user_id, username, ip, action, success） |
| `login_locks` | IP 锁定（ip, failed_count, locked_until） |
| `system_settings` | 系统配置（key-value） |
| `invite_codes` | 邀请码（code, max_uses, used_count, expires_at） |
| `module_permissions` | 模块权限（module_key, min_tier） |
| `feedback` | 用户反馈（user_id, module_key, type, title, content） |

### 2.4 用户等级体系（tier）

| tier | 标签 | 权限 |
|------|------|------|
| 0 | 普通客户 | 基础模块访问 |
| 1 | 重要客户 | 更多模块访问 |
| 2 | 团队成员 | 团队工作台 + 产品提交 |
| 3 (is_admin) | 管理员 | 全部权限 |

### 2.5 认证流程

```
注册 → username + password + display_name + invite_code(可选)
        ↓
密码哈希：hashlib + random salt → password_hash + salt 存入 users
        ↓
登录 → username/display_name 匹配（大小写不敏感）+ 密码验证
        ↓
成功 → 生成 UUID session token → 存入 sessions 表 → 返回前端
        ↓
前端存 localStorage['gamt_token'] → 后续请求 Authorization: Bearer <token>
```

### 2.6 安全机制

- **IP 锁定：** 同一 IP 连续失败 5 次，锁定 10 分钟
- **密码哈希：** hashlib + random salt（非明文存储）
- **会话过期：** token 有 expires_at，过期自动失效
- **Admin 保护：** `set_tier` 只能改 `is_admin=0` 的用户，admin 不能被降级
- **登录日志：** 所有登录尝试（成功/失败）记录 IP + 时间

### 2.7 管理后台功能（admin.html）

- 用户列表（按等级分组：管理员/团队/重要客户/普通客户）
- 等级调整（带确认弹窗 + toast 反馈）
- 密码重置
- 用户禁用/启用/删除
- 邀请码管理（创建/查看/启停/删除）
- 模块权限配置（每个模块设置最低 tier）
- 团队列表 tab（团队成员统计 + 活跃度 + 移出团队）
- 登录日志查看
- 邮件订阅者管理

### 2.8 API 路由汇总

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| POST | /api/auth/register | 公开 | 注册 |
| POST | /api/auth/login | 公开 | 登录 |
| POST | /api/auth/logout | 登录 | 登出 |
| GET | /api/admin/users | admin | 用户列表 |
| POST | /api/admin/toggle-user | admin | 启停用户 |
| POST | /api/admin/delete-user | admin | 删除用户 |
| POST | /api/admin/reset-password | admin | 重置密码 |
| POST | /api/admin/set-tier | admin | 设置等级 |
| POST | /api/admin/set-module-permission | admin | 模块权限 |
| GET | /api/email-subscribers | admin | 查看订阅者 |
| POST | /api/email-subscribers | admin | 更新订阅者 |
| GET | /api/admin/fund-asset-pool | team+ | 产品池 |
| POST | /api/admin/fund-asset-pool/submit | team+ | 提交产品 |

## 三、两套系统的关系

```
用户管理系统（auth.py + users.db）
    │
    ├── 控制看板访问权限（tier → 模块可见性）
    ├── 管理后台入口（admin.html，仅 is_admin=1）
    ├── 团队工作台入口（team.html，仅 tier>=2）
    │
    └── 邮件推送系统（独立于用户系统）
         ├── 订阅者列表独立存储（email_subscribers.json）
         ├── 管理入口复用 admin 权限校验
         └── 发送不依赖用户登录态，由 cron 触发
```

**关键区别：**
- 用户系统管的是"谁能看看板"（登录 + tier 权限）
- 邮件系统管的是"谁能收日报"（订阅者列表，与看板账号无关）
- 两套系统共享 admin 权限校验，但数据完全独立
- 邮件订阅者不需要有看板账号，看板用户也不自动收邮件

## 四、部署注意事项

- `users.db` 本地和腾讯云各自独立，密码不同（本地 `012911hby` / 腾讯云 `gamt2026`）
- `email_subscribers.json` 腾讯云为准，deploy_sync 可能覆盖
- 邮件发送只在腾讯云 cron 执行，本地不发
- 前端 `gamt_token` 是 localStorage key，两个域名（dashboard.gamtfof.com / cn.gamtfof.com）的 token 不互通
