## 正文

# Git 冲突标记潜伏导致的连环故障（2026-05-12）

## 问题现象
1. 用户登录后，左上角登录遮罩残留不消失
2. 推送代码后触发 Cloudflare 502 错误
3. Git 推送反复失败（本地和远程分叉）

## 根本原因
之前某次 `git stash pop` 或 `merge` 操作留下了冲突标记（`<<<<<<< Updated upstream` / `=======` / `>>>>>>>>`）没清理，潜伏在代码里：
- `index.html` 有 3 处冲突标记 → 浏览器解析 HTML/JS 时结构错乱 → 登录遮罩隐藏逻辑被打断
- `server/auth.py` 有 1 处冲突标记 → Python 语法错误 → 后端无法启动 → 502

**为什么之前没暴露？**
- 后端一直没重启，所以 auth.py 的语法错误没触发
- 前端浏览器缓存，所以 index.html 的问题没显现
- 今天用户刷新 + 我触发部署重启 → 两个雷同时响了

## 故障链路
```
用户刷新看板 → 登录遮罩残留（index.html 冲突标记）
    ↓
我修复 + push Gitee → 腾讯云自动同步 + 重启后端
    ↓
auth.py 冲突标记导致 Python 语法错误 → 9876 起不来
    ↓
Cloudflare Tunnel 找不到 localhost:9876 → 502
    ↓
本地和 Gitee 分叉（腾讯云 cron 自动 commit 数据）→ push 被拒
    ↓
反复 rebase/cherry-pick + zsh 括号解析问题
```

## 修复步骤
1. **腾讯云 auth.py**：`sed` 删冲突标记 → `py_compile` 验证 → 重启 9876 → 502 消失
2. **本地 index.html**：Python 脚本清理 3 处冲突标记（删除 2188 行冲突代码）
3. **Git 对齐**：`reset` 到 Gitee 最新 → `cherry-pick` 修复 commit → push 成功
4. **腾讯云同步**：`git reset --hard origin/main` → 三端对齐到 `8c1caa5c`

## 防御措施（已犯两次）
**三端对齐前的强制检查清单：**
```bash
# 1. 扫描冲突标记（本地 + 腾讯云都要跑）
grep -r "<<<<<<" . --exclude-dir=.git --exclude-dir=venv --exclude-dir=node_modules

# 2. Python 语法检查（关键文件）
python3 -m py_compile server/*.py

# 3. 前端关键文件完整性
wc -l index.html  # 应该约 11480 行，不应有大幅波动

# 4. Git 状态确认
git status --short  # 工作区应该干净
git log --oneline -5  # 确认最新 commit 符合预期
```

**部署前验证（腾讯云）：**
```bash
# 1. 同步前先备份当前运行版本
cp server/auth.py /tmp/auth.py.backup

# 2. 同步后先验证语法再重启
git reset --hard origin/main
python3 -m py_compile server/*.py
# 通过后再 pkill -f refresh_server.py && python3 server/start_refresh.py
```

## 技术细节
- **冲突标记格式**：`<<<<<<< Updated upstream` / `=======` / `>>>>>>> Stashed changes`
- **影响范围**：
  - HTML/JS：浏览器把冲突标记当文本渲染，打断代码结构
  - Python：冲突标记是非法语法，直接 SyntaxError
- **潜伏条件**：文件不被重新加载（后端不重启 / 前端有缓存）

## 教训
1. **Git 操作后必须检查冲突标记**，尤其是 `stash pop` / `merge` / `rebase` 后
2. **部署前必须跑语法检查**，不能依赖"之前能跑"
3. **三端对齐是高风险操作**，必须有 checklist，不能凭感觉
4. **这是第二次犯同样的错**，说明 checklist 没有固化成肌肉记忆
