# GAMT 登录界面自动登录前抖动修复（2026-05-05）

## 现象
打开 dashboard.gamtfof.com / cn.gamtfof.com，自动登录成功前的一两秒，登录框出现、然后挪一下位置再淡出。手机端（iPhone Safari）更明显。

## 根因（读代码后）
1. **默认就显示登录框**：`loginOverlay` 元素初始不带 `.hidden`，页面加载即渲染，然后 JS 才异步调 `/api/auth/me` 验 token，检查要 200-500ms 窗口，期间登录框实实在在显示。
2. **手机地址栏收起导致视口高度变化**：容器原来用 `inset:0` + `display:flex` 居中，手机浏览器首次加载时 URL bar 收起动画会让 `100vh` 瞬间变大，flex 被迫重新居中，登录框挪一下。
3. **backdrop-filter + will-change:transform** 放大了视觉感知。

## 修复（只动两行 CSS）
`~/Desktop/gamt-dashboard/index.html` 第 246 / 250 行：

**`.login-overlay`**：
- 去掉 `display:flex; align-items:center; justify-content:center`
- 从 `inset:0` 改成 `width:100vw; height:100vh; height:100svh`（svh = small viewport height，地址栏收起后也不会变）

**`.login-box`**：
- 从 `position:relative` 改成 `position:absolute; top:50%; left:50%; transform:translate(-50%,-50%)`（自己锁死正中，不再问父容器要 flex 居中）
- 加 `contain:layout`（隔离内部布局变化，不触发父级重排）

## 效果
- 登录框视觉位置、fade 动画完全一样
- 子项（input 自动填充 / backdrop-filter 重算 / 字体微变）任何变化都不再触发父容器重排
- 手机地址栏收起免疫（svh 不变）
- 自动登录场景下观感从"抖一下"变成"平滑淡出"

## 弯路记录
- 首次方向判断错了：怀疑过浏览器 `-webkit-autofill` 样式切换 + canvas 动画。看代码发现这是**已登录 → token 静默验证**路径，根本不走 autofill。
- 教训：抖动类问题先看"元素生命周期（何时出现、何时隐藏）"比看"CSS 细节"优先级高。
