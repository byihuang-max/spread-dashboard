## 正文

# Git 冲突标记导致登录遮罩残留 — 三次事故复盘

## 核心结论
登录遮罩不消失的根因是 git 冲突标记（<<<<<<< / ======= / >>>>>>>）残留在代码文件中。

## 故障链路

```
git stash pop / merge / rebase
    ↓
冲突标记残留
    ↓
前端（index.html）：JS结构被打断 → overlay隐藏逻辑不执行 → 遮罩永远挡着
后端（auth.py）：Python SyntaxError → 9876起不来 → 502
```

## 三次事故对比

| 次数 | 日期 | 根因 | 漏洞 |
|------|------|------|------|
| 第1次 | 5月初 | index.html + auth.py 冲突标记 | 没有检查流程 |
| 第2次 | 5月12日 | 同上 | 修了但没固化 |
| 第3次 | 5月13日 | index.html 冲突标记（腾讯云残留） | 只查本地没查腾讯云 |

## 快速修复 SOP（30秒内定位+修复）

```bash
# 1. 确认是否是冲突标记问题（线上）
curl -s https://dashboard.gamtfof.com/ | grep -c "<<<<<<" 

# 2. 腾讯云扫描
ssh ubuntu@111.229.129.146 "cd /home/ubuntu/gamt-dashboard && grep -rn '<<<<<<' . --exclude-dir=.git --exclude-dir=venv --include='*.html' --include='*.py' --include='*.js'"

# 3. 一键清理（保留 Updated upstream 版本）
ssh ubuntu@111.229.129.146 "cd /home/ubuntu/gamt-dashboard && python3 -c \"
import re
for f in ['index.html', 'admin.html', 'server/auth.py']:
    try:
        c = open(f).read()
        if '<<<<<<' in c:
            r = re.sub(r'<<<<<<< Updated upstream
(.*?)
=======
.*?
>>>>>>> Stashed changes', r'\1', c, flags=re.DOTALL)
            open(f,'w').write(r)
            print(f'Fixed: {f}')
    except: pass
\""

# 4. 验证 + 重启
ssh ubuntu@111.229.129.146 "cd /home/ubuntu/gamt-dashboard && python3 -m py_compile server/*.py && pkill -f refresh_server.py && nohup python3 server/start_refresh.py > /tmp/refresh.log 2>&1 &"

# 5. commit + push
ssh ubuntu@111.229.129.146 "cd /home/ubuntu/gamt-dashboard && git add -A && git commit -m 'fix: 清理冲突标记' && git push origin main"
```

## 防御：每次 git 操作后必跑

```bash
grep -r "<<<<<<" . --exclude-dir=.git --exclude-dir=venv --include="*.html" --include="*.py" --include="*.js"
python3 -m py_compile server/*.py
```

## 关键教训
- 本地干净 ≠ 线上干净，三端都要查
- stash pop / merge / rebase 后必须扫描冲突标记
- 第一反应：curl 线上 grep <<<<<<，不要先看代码逻辑
