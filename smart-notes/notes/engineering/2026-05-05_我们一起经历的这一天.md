## 时刻一 · GAMT 架构梳理 · 方法论先行

**事件：** 把 GAMT 看板的架构从 xmind v1（8 层平铺教科书分层）重写成 v2（A/B/C 三支：业务流 / 文件夹镜像 / 对客逻辑缺口）。

**Roni 的真正要求：** 不要分层教科书，要把 "择时重于选股、周期重于题材、个股先于情绪、情绪先于大盘" 这条方法论总纲放在顶上，让图能讲出"信息流是怎么走的"。

**我学到：** **架构不是分类，是叙事。** 同样的模块，按分类画出来像死的文件夹；按流向画出来像活的生产线。

**难的地方：** 把"PM 之间的翻译器"这个定位翻译成节点结构——它不是"模块 X 服务模块 Y"，而是"把人工语言压缩成可计算状态"。这种抽象关系我画了两版才想明白。

**产出：** 420 节点的 xmind v2 + 16 条对客逻辑缺口诊断（🔴/🟡/🟢 三级）。

## 时刻二 · Smart Notes 智能分类系统 · 用嵌入+LLM 解决语义搜索

**事件：** 从零搭建了一套 **本地 BGE 嵌入 + Claude LLM** 的混合智能分类管线。

**阶段 1（embedding 层）：**
- 本地 BGE-base-zh-v1.5（离线、免费）
- 向量化 86 篇老笔记 + 9 个类别中心
- 分类阈值：auto ≥0.60 / confirm 0.50-0.60 / new <0.50
- 迭代检测：语义相似度 + 标题 2-gram 重叠联合判定

**阶段 2（LLM 编排）：**
- Claude 中转 API 做标题 / 摘要 / 标签自动生成
- 灰区兜底：embedding 拿不准时 Claude 读原文仲裁
- 迭代 diff：自动生成"相比上一版的改动"段落
- 4 个文件串起来：`llm_client.py` / `note_pipeline.py` / `save_note.py` / `notes_intel.py`

**最漂亮的一个设计：** 巴西金融市场测试——embedding 把它归到 "conversations" 0.54（灰区），Claude 看完后仲裁到 "emerging_markets"（原本是空目录）。**系统自己激活了一个空类**。

**Roni 说的关键一句："不希望新类别太离散"** → 让我在 skill 里写死了"不自动建新类，必须人工确认"。

## 时刻三 · 笔记丢失 + SOUL 写入 + 第一个 skill 诞生

**这是今天最重要的一个闭环。**

### 12:50 写完架构诊断笔记

write 工具返回 "Successfully wrote 6053 bytes"。我对外汇报"已归档"。

### 16:30 发现笔记不存在

准备 commit 时：**磁盘上根本没这个文件**。工具报假成功，我信了。

### 误诊 → 真因

我第一反应怀疑 post-commit 钩子的 `rsync --delete` 删了它。查了半小时 reflog + sync 脚本，推翻自己——**2026-05-05 一整天根本没 commit 过**，钩子没跑；而且 rsync 方向不会动本地。

**真因：** 工具会静默假成功。同一会话 edit MEMORY.md 时又发生了一次，证实这是工具本身的模式。

### Roni 的一句话让事情升级

> "这个可以生成一个 skill 了？因为 soul 不可能如此完美，用 skill 来约束会好一点。"

这句话非常准。**SOUL 是理念层（软约束，我可能下次忘）。Skill 是操作层（硬约束，触发时强制读流程）。**

### 30 分钟后诞生第一个 skill：「写完就验」

位置：`~/.openclaw/workspace/skills/写完就验/`

结构：
- `SKILL.md`：4 步 checklist（验证 → Recovery → 判断重要性 → 汇报前核查）
- `_meta.json`：触发词
- `references/recovery.md`：4 个 Python 直写模板

实战测试：模拟工具假成功 → Step 1 抓到 → Recovery 模板 3 直写 → 重新验证通过。

### 第一次上工就兜住一个真问题

写完 skill 后，跑 `backup-memory.sh` 备份，我用"写完就验"流程验证时发现——**备份脚本根本不同步 `skills/` 目录**，skill 只在 git 里没上桌面。立即改了脚本，第二次备份全绿。

**Skill 刚诞生就证明了自己的价值。**
