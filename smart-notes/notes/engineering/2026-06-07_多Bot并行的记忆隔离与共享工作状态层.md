## 摘要

Hermes多Bot并行开发时记忆物理隔离导致进度不共享，解法是区分memory（长期偏好）与进度（短期状态），建立Smart Notes共享黑板、Git提交记录、Kanban任务板三层共享架构。

## 正文

多 Bot 并行开发的记忆隔离问题与共享工作状态层机制

问题根源：Hermes 每个 Bot = 独立 profile，记忆物理隔离在各自 ~/.hermes/profiles/<名字>/memories/ 里。并行开发时早上 Bot A 干的活，下午 Bot B 读不到。

关键认知：memory 不该装工程进度。memory = 长期偏好/环境/约定；进度 = 今天改了啥（一周后是垃圾）。解法不是打通记忆，而是建共享工作状态层。

三层共享架构：
1. Smart Notes（共享黑板）—— 路径 /Users/apple/Desktop/gamt-dashboard/smart-notes/，不属于任何 profile，所有 Bot 共享。开工搜、收工存。适合工程进度/决策/架构地图。
2. Git 提交记录（代码真相）—— gamt-dashboard 是 git 仓库，改动只要 commit 任何 Bot git log 可见。代码真相永远在 git 里不在记忆里。
3. Kanban（任务分工）—— hermes kanban，Hermes 原生跨 profile SQLite 任务板，适合多 Bot 并行时分工认领。

职责分流：今天进度→Smart Notes；代码改动→Git；任务分工→Kanban；Bot偏好→各自memory（不塞进度）。

推荐习惯：开工搜Smart Notes+git log，干活改源头不改产出，收工存Smart Notes+git commit。
