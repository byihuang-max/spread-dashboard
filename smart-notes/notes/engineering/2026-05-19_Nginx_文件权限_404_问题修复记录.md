# Nginx 文件权限 404 问题（2026-05-19 彻底修复）

## 大白话解释

**问题：** 网站突然 404，文件明明在服务器上，但访问不了。

**原因一句话：** 我们换了"谁来读文件"，新的读者没有钥匙进门。

**类比：** 
- 之前：你（ubuntu）自己开门拿文件给客人看 → 你有钥匙，没问题
- 现在：你让管家（Nginx/www-data）去拿文件给客人 → 管家没钥匙，进不了房间

**为什么"修好了又犯"：**
每次代码同步（git pull / rsync），新拉下来的文件夹又是"锁着的"（权限 700）。就像每次搬新家具进来，门又自动上锁了，管家又进不去。所以必须在每次同步后自动开锁（chmod），不能只开一次。

## 技术架构变更

之前：Tunnel → Python 9876（ubuntu用户读自己文件，权限无所谓）
现在：Tunnel → Nginx 80（www-data用户读ubuntu文件，需要other权限）

## 触发链

git reset / rsync → 新目录权限700 → www-data进不去 → 404

## 修复

每次同步后自动 chmod -R o+rX ~/gamt-dashboard/
覆盖两条链路：sync-to-cloud.sh + deploy_sync.sh

## 为什么不改umask/git config

git reset --hard 不看 umask；同步后统一chmod最简单可靠无副作用。
