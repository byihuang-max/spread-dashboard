## 团队代码包（Nova Demo）的 8 个问题

1. **一个文件干了所有事** — app.py 塞了页面/样式/接口/数据/权限/渲染，改一行可能全站崩。→ 拆开，各归各位。
2. **路径写死了** — 硬编码 `/var/root/.openclaw/workspace`，换机器跑不起来。→ 用相对路径或环境变量。
3. **源码和交付物混在一起** — 源代码/zip/审阅版/交付版全堆一个文件夹。→ src/dist/docs 分层。
4. **数据文件没有说明书** — 十几个 JSON 没人知道字段谁生成谁消费。→ 每个配 schema + 来源 + 版本。
5. **研究代码和展示页面绑死了** — 改策略牵动页面，改页面影响策略。→ 研究产 JSON，页面只读 JSON，schema 隔开。
6. **换台机器跑不起来** — 没 requirements.txt/部署文档。→ 补齐依赖清单和部署说明。
7. **密码放在网址里** — `?secret=xxx` 会进浏览器历史/日志。→ 改用 cookie/token。
8. **产品定位不清楚** — 同时叫 Nova/GAMT/Multiasset/HFN/Weather/Stock。→ 一个名字一句话说清楚。

## GAMT 自己的 10 个改进方向

1. **功能太多，客户不知道买的是什么** → 拆成 3-4 条产品线（Macro Radar / Manager DD / Event Radar / Daily Brief），每条一句话说清。
2. **谁能看什么没分清楚** → 建角色权限表（admin/内部/客户/试用/只读），前后端都拦。
3. **哪些数据能给客户看没标清楚** → 每个字段打标签 internal_only / client_viewable / public。
4. **首页是模块目录不是决策入口** → 改成"今日决策工作台"：环境/策略/事件/基金/风险五条结论，点进去看证据。
5. **数据很多但不告诉用户"所以呢"** → 每个模块统一五段式输出：结论→证据→历史→风险→动作。
6. **数据格式各写各的** → 定统一 schema，API v1 承诺格式稳定。
7. **改了代码直接上线没缓冲** → 加 staging 环境，测通再上正式。
8. **日更跑没跑成功只有 SSH 才知道** → Admin Health 页面：状态/时间/失败原因/手动重跑。
9. **尽调库缺审计链** → 加版本链+审批记录+附件审计+可见范围。
10. **模块名字像内部黑话** → 翻译成客户秒懂的话（耐心资本→主动资金在不在场，HALO→高盛在买什么，红灯→有没有踩雷信号）。

---

## 核心判断

GAMT 技术底子比团队包强很多，但现在还是"Roni 自己能用"的系统。下一步要变成"陌生客户进来 30 秒就知道今天该看什么、信什么、怎么做"的产品。

## 优先级排序

| 级别 | 内容 | 一句话 |
|------|------|--------|
| P0 | 权限/数据暴露边界 | admin vs client 彻底分离 |
| P1 | 商业首页 | 决策工作台 + 五段式输出 |
| P2 | 数据契约 | schema 化 + API v1 稳定 |
| P3 | 部署隔离 | staging/prod + 失败回滚 |
| P4 | 尽调库产品化 | 审批/版本/可见范围/审计 |
| P5 | 报告化输出 | PDF/网页，可转发投委会 |
