# GAMT 看板登录遮罩 Bug 修复记录（2026-05-09）

## 问题现象
- 用户访问 dashboard.gamtfof.com 时，登录遮罩层一直不消失
- 页面能加载，后端接口正常，但登录成功后遮罩仍然挡住页面
- 之前从未出现过此问题

## 根本原因
登录成功后，`showApp()` 函数只给遮罩添加了 CSS class `.hidden`，但该 class 只设置了 `opacity:0` 和 `pointer-events:none`，元素本身还在文档流中。在某些情况下（浏览器缓存/渲染引擎边界/前端改动冲突），会导致 class 切换和实际渲染状态不同步。

## 修复方案
commit `a5ad03ed` 在 `showApp()` 中实施三重保险：
```javascript
overlay.classList.add('hidden');           // 原有逻辑
overlay.style.display='none';              // 强制隐藏
overlay.setAttribute('aria-hidden','true'); // 无障碍标记
```

## 核心教训
1. **前端状态切换不能只依赖 CSS class**：关键 UI 状态（登录遮罩/模态框）需要多层保险
2. **开源风险预判**：这类 bug 在不同浏览器/环境下更容易触发，必须提前加固
3. **登录流程是第一道门槛**：任何卡住都是严重体验问题

## 后续建议
如果再出现"已登录但遮罩还在"，可加兜底：页面加载完 3 秒后检测状态，自动强制移除遮罩。
