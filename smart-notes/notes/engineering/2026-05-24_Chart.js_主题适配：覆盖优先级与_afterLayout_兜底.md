## 摘要

将 GAMT 看板切换为黑底主题时，CSS 无法影响 canvas 内部样式，Chart.js options 存在三层覆盖优先级，硬编码会屏蔽全局默认值；正确做法是用 afterLayout 钩子在 scale 初始化完成后强制覆写样式，避免 beforeUpdate 污染内部状态。

## 正文

标题：Chart.js 主题适配的覆盖优先级与 afterLayout 兜底套路

背景：把 GAMT 看板从白底改成 Bloomberg 黑底橙字主题。CSS 全局 override 能搞定 HTML 容器，但 Chart.js 渲染的是 canvas，CSS 完全管不到图表内部的 grid 线、刻度色、轴标题色。

第一坑：CSS 改不了 canvas
- 加再多 !important 也没用，必须从 chart.js API 入手。

第二坑：覆盖优先级
Chart.js 的 options 解析有三层，从弱到强：
1. Chart.defaults（全局默认）
2. Chart.registry.getScale('linear'|'category'|'time').defaults（scale 类型默认）
3. new Chart(canvas, {options:{scales:{x:{grid:{color:'#f0f0f0'}}}}})（实例硬编码，最强）

只要业务代码里写死了 grid:{color:'#f0f0f0'}，前两层默认值全部无效。本次踩坑：IV 期限结构图永远是浅灰横线，改了 defaults 没反应。

第三坑：beforeUpdate 钩子时机太早
最早尝试用 Chart.register({beforeUpdate}) 改 scale.options，结果污染了 time scale 内部状态，date-fns adapter 报 "t.startsWith is not a function"。原因：chart.js 在 beforeUpdate 时正在初始化 scale，options 引用还在加工中，乱改会破坏内部解析流程。

正解：afterLayout 钩子兜底
在 chart.js 已经把 scales 全部初始化完之后再改：
```
Chart.register({
  id:'bbGridLate',
  afterLayout:function(chart){
    Object.values(chart.scales||{}).forEach(function(scale){
      if(scale.options.grid&&scale.options.grid.display!==false){
        scale.options.grid.color='rgba(255,140,0,0.07)';
        scale.options.grid.tickColor='#2a2a2a';
        scale.options.grid.lineWidth=1;
      }
      if(scale.options.border) scale.options.border.display=false;
      if(scale.options.ticks) scale.options.ticks.color='#888';
      if(scale.options.title&&scale.options.title.display) scale.options.title.color='#ff8c00';
    });
  }
});
```

为什么这招稳：
- 时机：scale 已构建完成，不会破坏 time scale 内部状态
- 优先级：直接改 scale 实例的 options，等于在第三层之后又加了一层，硬编码挡不住
- 触发：每次 render/resize 之前都跑一次，主题切换/数据更新都覆盖

通用教训：
1. canvas 类组件做主题，必须从 API 钩子层走，不能靠 CSS
2. 改默认值无效时，一定要看业务代码里有没有硬编码（grep 'color' '#f0f0f0' 等）
3. 钩子选 afterLayout 不选 beforeUpdate，避免污染初始化中间状态
4. 写覆盖逻辑时，尊重业务里的 display:false（grid 显式关掉的别强行画）
