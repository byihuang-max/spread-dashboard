# 团队基金推荐模块说明书：申请、审批、上线全流程

## 1. 角色与页面

```
团队成员
  └─ team.html：提交候选基金

管理员 admin
  └─ admin.html：审批、通过、拒绝、下架

系统脚本
  ├─ pool_api.py：维护产品池 fund_asset_pool.json
  ├─ fetch_data.py：按产品池拉火富牛净值数据
  └─ render_html.py：把最新数据渲染成 fund_asset.html

前端用户
  └─ fund_asset.html：查看正式上线后的团队基金推荐页
```

## 3. 团队成员提交流程

### 3.1 入口

团队成员访问：

```
/team.html
```

### 3.2 必填字段

提交时必须填写：

```
产品代码：如 AWR20B
产品名称：如 彬元天源量化B类
产品分组：如 量选类
策略细分：如 量化选股
推荐理由：不少于系统要求的最短长度
```

### 3.3 前端请求

前端向后端发送：

```http
POST /api/admin/fund-asset-pool/submit
Content-Type: application/json
```

示例 body：

```json
{
  "code": "AWR20B",
  "name": "彬元天源量化B类",
  "group": "量选类",
  "detail": "量化选股",
  "reason": "团队推荐，策略表现优秀，纳入观察池",
  "submitted_by": "黄晴梦"
}
```

## 4. 后端入池逻辑

### 4.1 API 路由

文件：

```
server/refresh_server.py
```

核心接口：

```python
/api/admin/fund-asset-pool/submit
```

该接口负责读取前端 body，并调用：

```python
pool_api.submit_product(
    code=body.get('code', ''),
    name=body.get('name', ''),
    group=body.get('group', ''),
    detail=body.get('detail', ''),
    reason=body.get('reason', ''),
    submitted_by=current_user
)
```

### 4.2 产品池写入

文件：

```
fund-asset-recommend/scripts/pool_api.py
```

核心要求：

```python
if not name:
    return False, '产品名称不能为空'
```

写入文件：

```
fund-asset-recommend/data/fund_asset_pool.json
```

典型记录结构：

```json
{
  "code": "AWR20B",
  "name": "彬元天源量化B类",
  "group": "量选类",
  "detail": "量化选股",
  "status": "pending",
  "reason": "团队推荐，策略表现优秀，纳入观察池",
  "submitted_by": "黄晴梦",
  "submitted_at": "2026-05-07 22:54:14",
  "verified": true,
  "reviewed_by": null,
  "reviewed_at": null,
  "review_note": null

```

## 5. admin 审批流程

### 5.1 入口

管理员访问：

```
/admin.html
```

进入产品池管理/团队基金优选审批区。

### 5.2 审批接口

```http
POST /api/admin/fund-asset-pool/review
Content-Type: application/json
```

通过示例：

```json
{
  "code": "AWR20B",
  "action": "approve",
  "review_note": "通过，纳入团队基金推荐",
  "reviewed_by": "admin"
}
```

拒绝示例：

```json
{
  "code": "AWR20B",
  "action": "reject",
  "review_note": "信息不完整，暂不纳入",
  "reviewed_by": "admin"
}
```

### 5.3 审批后状态

通过后：

```json
{
  "status": "approved",
  "reviewed_by": "admin",
  "reviewed_at": "2026-05-08 01:35:00"
}
```

只有 `approved` 状态的产品会进入正式展示链路。

## 6. 从审批通过到真实上线

审批通过只代表产品进入正式产品池，**还不等于前端页面已经展示**。

必须继续执行数据生成链路：

```
fund_asset_pool.json
   │
   ▼
fetch_data.py
   │
   ▼
fund_asset_latest.json
   │
   ▼
render_html.py
   │
   ▼
fund_asset.html
   │
   ▼
线上页面展示
```

---

## 7. 手动上线命令

当管理员审批通过后，如果需要立即上线，不等定时任务，可在腾讯云执行：

```bash
cd /home/ubuntu/gamt-dashboard/fund-asset-recommend/scripts
python3 fetch_data.py
python3 render_html.py
```

执行后检查：

```bash
cd /home/ubuntu/gamt-dashboard/fund-asset-recommend
ls -lh fund_asset.html data/fund_asset_latest.json
grep -n "AWR20B\|彬元天源" fund_asset.html | head
```

如果 grep 能找到产品代码或产品名，说明前端数据包已经生成。

## 8. 定时任务上线逻辑

日常情况下，产品审批通过后可以由系统定时任务自动刷新。

模块在 GAMT 更新链路中的注册位置：

```
server/module_registry.py
```

团队基金推荐模块包含：

```python
('fund-asset-recommend/scripts', 'fetch_data.py')
('fund-asset-recommend/scripts', 'render_html.py')
```

定时任务运行后，会自动：

```
读取 approved 产品
→ 拉取净值数据
→ 生成 latest json
→ 渲染 HTML
→ 前端生效
```

## 10. 数据保护要求

`fund_asset_pool.json` 是线上业务数据，团队成员和管理员会直接在网站上写入。

因此部署同步时必须排除，不能用本地旧文件覆盖云端。

当前已在：

```
scripts/sync-to-cloud.sh
```

加入排除：

```bash
--exclude=fund-asset-recommend/data/fund_asset_pool.json \
--exclude=fund-asset-recommend/data/fund_asset_pool.json.bak \
```

同时排除其他线上业务数据：

```bash
--exclude=env_fit/momentum_stock/email_subscribers.json \
--exclude=server/users.db \
--exclude=server/users.db-shm \
--exclude=server/users.db-wal \
```

原则：

```
代码从本地同步到云端
业务数据留在云端生产环境
```

## 11. 常见问题

### Q1：admin 审批通过了，为什么前端还看不到？

因为审批只更新 `fund_asset_pool.json`，还需要执行：

```bash
cd /home/ubuntu/gamt-dashboard/fund-asset-recommend/scripts
python3 fetch_data.py
python3 render_html.py
```

### Q2：产品名为空怎么办？

新版已强制产品名必填。若仍为空，检查：

```
team.html 是否已更新
admin.html 是否已更新
refresh_server.py 是否传 name
pool_api.py 是否校验 name
```

### Q3：页面显示旧数据怎么办？

先确认服务端 HTML 是否已更新：

```bash
grep -n "产品代码\|产品名称" /home/ubuntu/gamt-dashboard/fund-asset-recommend/fund_asset.html | head
```

如果服务端已更新，前端仍旧，通常是浏览器缓存，强刷或重新打开页面。

### Q4：为什么不能把本地 fund_asset_pool.json 同步到云端？

因为云端是生产写入源。团队成员提交、admin 审批都直接写云端文件。本地文件可能是旧的，一旦 rsync 覆盖，会导致线上新增产品丢失。

## 12. 推荐标准操作 SOP

```
1. 团队成员在 team.html 提交产品
2. 系统写入 fund_asset_pool.json，状态 pending
3. admin 在 admin.html 审核
4. 通过后状态改为 approved
5. 立即上线：手动执行 fetch_data.py + render_html.py
6. 检查 fund_asset.html 是否包含产品代码/名称
7. 刷新前端页面确认展示
8. 后续定时任务自动更新净值和页面
```
